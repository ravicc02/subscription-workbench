# 独立订阅推送工作台方案

状态：总体目标方案，更新于 2026-10-23。独立项目已提供 v0.3.3 可运行版本；已实现及待适配范围以 docs/status.md 和实际代码为准。本文中的 AstrBot 原实现路径用于说明迁移来源，不代表新项目仍依赖该运行时。

## 产品定位与范围

将现有 Harness 扩展为独立的订阅推送工作台，统一管理来源、订阅规则、工作区、模型、Bot、平台账号和推送记录。启动、管理登录、任务调度、模型调用和消息发送均不要求运行 AstrBot。

内容范围覆盖新闻资讯、公告、技术文章、版本发布、文档更新、数据指标变化和业务告警等。新闻作为内置场景配置，继续使用已有金融与时政来源、整理规则和快讯模板；通用流程不固定新闻分类、原文链接或走势分析字段。

平台范围以 AstrBot 支持的平台及通道类型为适配目标，包含其内置适配器和社区适配器对应的接入方式。建立可扩展的通道注册表，按通道逐个适配并验证，不把微信写死在核心配置、接口和投递队列中。

工作区就是服务所在机器上实际存在的本地目录，用于保存 Agent 文档、订阅规则、原始输入、处理结果和运行记录。新增机器人接入成功后自动绑定该目录，支持独立目录或多个机器人共用同一目录。目录绑定和文件访问范围以服务端解析的实际路径为准，不仅创建一个界面上的工作区名称。

首版围绕订阅和推送建立完整闭环，不默认增加通用聊天平台或远程插件市场。来源、处理和投递通过插件扩展。

## 核心对象

| 对象 | 职责与关系 |
| --- | --- |
| 平台适配器 | 封装平台协议、连接生命周期、能力声明、消息渲染及发送结果 |
| 平台账号 | 机器人配置中的实际接入信息，内部保存认证、连接状态和凭据引用，不要求用户另建账号对象再关联 |
| Bot | 通过扫码或平台参数接入的实际机器人实例，包含名称、类型、接入配置、连接状态、推送目标和本地工作区绑定 |
| 推送目标 | 具体账号下的私聊、群聊、频道、话题或 Webhook 接收端，保存平台所需的目标与上下文 |
| 工作区 | 服务所在机器上的实际目录，系统记录目录标识及路径；可以由一个机器人独立使用，也可以由多个机器人共用 |
| 来源 | RSS、网页、API、Webhook 或其他输入的连接配置及采集策略 |
| 订阅 | 工作区对来源、内容范围及触发条件的选择，包含处理规则和推送策略 |
| 投递路由 | 根据机器人绑定的本地工作区和接收目标自动建立，内部记录格式、投递策略和发送结果，不作为新增机器人的前置步骤 |
| 内容事件 | 来源的一次新增、变更或条件触发，串联输入、处理、产物与每路投递状态 |

产品中的“新增机器人”就是接入一个真实平台机器人，不再创建额外的逻辑机器人。平台账号、接收目标和投递记录保留内部数据边界，但由同一接入流程配置。每个机器人绑定一个本地工作区，可以有多个真实接收目标；多个机器人可以绑定同一个目录，共享订阅和处理产物。

## 新增机器人的三步流程

### 第一步：命名并选择类型

填写机器人名称，选择平台及接入类型。类型决定下一步的配置表单，界面仅提供已实现接入流程的平台类型。机器人 ID 由系统生成，不要求用户填写会话 UMO、平台账号 ID 或投递路由 ID。

### 第二步：按类型完成接入配置

配置表单由适配器的配置结构和接入能力生成：

- 扫码接入类型：生成二维码、展示有效状态，扫描完成后保存真实登录状态，检查连接并继续；二维码过期可以刷新。
- 参数接入类型：填写该通道需要的 Token、应用参数、服务地址、Webhook 或其他认证字段，保存并验证连接。
- 回调或长连接类型：展示必要的回调地址或连接参数，由适配器接收验证并维护连接状态。

接收目标属于同一次平台配置。已能获取的私聊、群聊或频道可直接选择；需要手工标识的通道按平台表单填写。需要先收取一条消息才能建立上下文时，展示待接收目标状态，并在上下文建立后绑定选定会话。扫码只确认账号登录，不凭空推断收件人或把账号自身当成推送目标。

接入配置、凭据和会话上下文保存在服务端机器人状态目录。认证或连接失败时保留填写进度并显示原因，不将保存参数视为已连接。

### 第三步：自动绑定本地工作区

接入成功后，系统自动完成目录绑定、规则文件初始化及投递关系建立，不要求用户先去工作区页面创建对象，也不新增一个必填的工作区配置向导。

默认创建独立目录 `workspaces/bots/<bot-id>/`。创建界面可展开本地工作区设置，选择以下方式：

- 独立使用：自动创建默认目录，也可以指定服务端允许的本地目录。
- 共用工作区：选择已有目录，或使用默认共享目录 `workspaces/shared/`；后续机器人选择同一目录即加入该工作区。

界面显示解析后的实际本地路径和使用该目录的机器人。网页运行在另一台电脑时，本地目录仍指服务端主机目录；目录选择由服务端目录接口完成。

新目录初始化 `AGENTS.md`、`docs/`、`data/raw/`、`data/processed/`、`reports/` 和 `runs/`。绑定已有目录时，检查结构和访问权限，只补缺失文件，不覆盖已有规则或产物。同一实际目录登记为同一个工作区，不能因路径别名产生重复调度。

绑定成功后，机器人直接使用该目录的订阅、规则和默认模型。默认启用后续符合条件的真实推送，沿用首次只建历史基线的规则，不补发绑定前的内容。没有订阅或目标上下文尚未建立时，分别展示待订阅或待接收目标，不伪造发送成功。

用户看到的完成结果是：机器人名称、平台类型、真实连接状态、接收目标和本地目录。发送走该平台的真实通道；微信机器人投递到配置的微信会话，其他平台投递到各自目标。

## 内容与触发方式

| 类型 | 示例 | 判重与触发依据 |
| --- | --- | --- |
| 新增内容 | 新闻、公告、博客、版本发布 | 来源外部 ID 或规范化链接，结合必要的内容版本 |
| 内容变更 | 文档、指定网页、状态页 | 已建立的初始快照与有效内容变化，过滤无关动态字段 |
| 条件事件 | 指标越过阈值、服务状态改变 | 规则版本、对象、状态变化及稳定事件 ID，配置去抖和恢复条件 |
| 外部事件 | 业务 Webhook、任务完成通知 | 已认证的来源事件 ID、时间及重放保护 |

支持轮询发现、Webhook 接入和人工验证。新增内容默认首次建立历史基线，不补发旧内容；网页和指标先建立初始快照。收到相同事件时保持幂等，不因轮询重复推送。

即时推送是现有新闻订阅的默认策略。其他订阅可选择合并窗口、频率上限、静默时段或配置式汇总，策略按订阅保存；迁移现有新闻订阅时继续使用即时推送，不恢复旧定时简报任务。

以下路径相对于现有 Harness 根目录。

| 当前实现 | 独立项目处理方式 |

| `plugins/market-news-bridge/polling.py` | 保留轮询间隔、错峰、同站限流、持久化冷却和 Retry-After 规则；补齐独立任务调度入口 |
| `plugins/market-news-bridge/storage.py` | 复用队列和恢复逻辑，将文章扩展为内容事件，扩展工作区、模型、平台账号、目标和投递路由表 |
| `plugins/market-news-bridge/configuration.py` | 保留版本冲突、工作区路径检查和 URL 检查；将现有 tenant 语义迁移为 workspace，替换宿主会话校验 |
| `plugins/market-news-bridge/main.py` | 提取采集、处理及投递服务；替换 Star 生命周期、RSS 插件注册和平台发送调用 |
| `plugins/market-news-bridge/agent.py` | 保留短提示词路由、文件权限和产物校验；独立实现模型工具循环，按内容模板选择校验规则 |
| `plugins/market-news-bridge/admin.py` | 复用管理操作语义；独立提供登录、权限和管理 API，扩展通用订阅及多平台对象 |
| `web/src/main.jsx` | 复用表格、编辑及回溯交互；改为独立 API，统一工作区用语，新增平台账号、模型和订阅策略管理 |
| `docs/` | 保留现有新闻规则为场景模板，新增通用事件入口和可选内容模板 |

现有 `polling.py` 提供规则与请求策略，完整 RSS 触发入口仍依赖 `astrbot_plugin_rss`。迁出时补齐独立调度入口，不能只复制规则文件就视为已经完成独立调度。

“模型复用”指继续使用用户已购买或部署的模型服务，并迁移经过检查的调用参数。AstrBot 模型供应商实例、会话对象和原生运行器需要替换。AstrBot 插件及平台适配器也需要逐个检查依赖并迁移或适配，不承诺原样加载。第三方源码及依赖按对应许可证要求使用和分发。

## 独立架构

```text
Web 订阅推送工作台
    → 独立管理 API、登录、权限与配置版本
        → 来源插件 + 调度器 / Webhook 接入
            → 标准内容事件 + 原始输入缓存
                → 工作区订阅匹配、判重及推送策略
                    → 直接转发 / 规则处理 / Agent 整理
                        → 标准产物与校验
                            → 投递路由与独立队列
                                → 平台渲染与分片
                                    → 平台适配器 → 各平台目标

原始输入、规则快照、模型调用、工具轨迹、标准产物及每路发送结果
    → 通过事件编号关联并在工作台回溯
```

建议沿用 Python 后端和现有 React 管理页。首版为一个服务进程、后台异步任务与 SQLite，只有一个进程拥有调度器和工作线程。后续需要多个 API 进程时，先补独立 worker 所有权、任务原子领取和租约恢复，避免多实例重复执行。

对公共来源，在相同采集配置和权限范围内共享输入缓存。同一工作区内相同内容版本、规则、模型和模板的处理结果可以复用，再投递到不同平台。不同工作区分别匹配和处理。私有 API、凭据或可见范围不同的来源按权限范围分区缓存，不按 URL 直接全局合并。

平台格式变化只生成目标通道的派生产物，不再次调用模型。平台专属内容要求若确实需要模型处理，应明确成为另一份处理配置，并独立记录调用和用量。

## 多平台 Bot 与通道能力

平台目录以 AstrBot 官方接入目录及所选版本的社区适配器清单建立基线，逐项登记平台、通道类型、认证方式、第三方依赖和适配状态。覆盖目标包括：

- 官方目录中的 QQ 官方机器人、企业微信应用、企业微信智能机器人、微信公众号、个人微信、飞书、钉钉、Telegram、LINE、Slack、Mattermost、Misskey、Discord 和 KOOK。
- 协议接入方式 OneBot v11 和 Satori，按实际后端及通道能力验证。
- 官方目录列出的社区接入 Matrix、VoceChat，以及后续纳入兼容目录的社区适配器。

同一平台的不同通道变体分别登记。普通 HTTP Webhook 也可作为独立输出插件。以上为目标范围，适配状态以本项目的兼容矩阵和真实测试为准。

独立服务使用自己的适配器接口：连接、断开、健康检查、接收必要回调、获取能力及发送。需要长连接的平台由服务维护连接，需要公开回调的平台提供校验后的回调入口。微信的账号状态和上下文维护归入对应通道适配器。

每个适配器声明：

- 支持的目标类型及地址结构。
- 认证、连接、回调和上下文依赖。
- 是否支持主动推送及其有效条件。
- 纯文本、Markdown、卡片、图片、文件和链接等格式能力。
- 长度、分片、发送频率及接口返回的限流要求。
- 可获得的发送回执、消息 ID、撤回和编辑能力。

核心消息使用结构化内容块和可用的纯文本回退。是否提供原文链接、数值或事件影响等字段由内容模板定义。发送前按目标平台渲染，格式不支持时明确降级；来源内容不能直接构造平台指令或突破模板字段边界。

适配器开发状态区分“规划中”“适配中”“真实验证通过”。机器人运行状态区分“待配置”“待扫码”“连接中”“已连接”“待接收目标”“重连中”“已暂停”和“连接失败”，按当前问题展示。产品中不提供虚拟机器人或模拟投递通道；“发送测试消息”也通过当前平台向选定真实目标发送。接入成功不等于已经获得主动推送所需的全部上下文。

当前项目使用 AstrBot 平台实例和 UMO 会话标识。新项目改用自己的平台账号、目标和路由 ID；旧 UMO 仅作为迁移来源信息。临时经 AstrBot 转发的适配器必须标记为过渡模式，不能计为已完成独立部署。

## 工作区与处理方式

本地工作区保存来源订阅、筛选规则、处理模式、模板及默认模型。机器人绑定目录时自动建立订阅到接收目标的投递关系；高级页面可以编辑投递策略，但不要求每次接入时再手工创建路由。

多个机器人共用一个目录时，共享该目录的文档、订阅、规则、处理结果和原始输入；每个机器人的登录凭据、会话上下文及发送状态分别保存。同一事件和有效配置只处理一次，再向各机器人目标独立投递。单个机器人暂停不影响其他机器人，也不重复创建来源轮询。

机器人使用不同独立目录时，规则与产物分别保存、分别处理。跨目录读取及账号目标绑定按权限校验，公共采集缓存仍可在授权范围内复用。将机器人改绑到另一目录时，切换后续任务使用的目录，保留旧产物，并处理或取消旧绑定的待发送任务，防止串发。

处理模式包括直接转发、确定性规则处理和 Agent 整理。简单通知可以按模板发送；需要筛选、归纳或分析的订阅使用模型，并记录实际使用的模式。

Agent 的流程按任务读取事件、工作区规则、原始输入和模板，保存处理结果、推送产物及执行记录。提示词只做指挥和路由。关注范围、排除内容、整理要求、模板及默认模型由工作区页面配置，按任务生成固定快照；Agent 的规则读取工具提供本工作区快照。旧文档仅作为一次性迁入来源，平台不再以编辑 Markdown 文件作为业务配置方式。事件提供输入类型、版本及指定输出路径，不要求每个事件都是文章或必须带 URL。

模型只获得本任务需要的读取工具与指定产物的写入权限，不默认获得终端、跨工作区数据、发送工具或修改规则的能力。采集和投递继续由服务负责。新闻原文与其他外部输入均视为资料，不能作为更改任务权限的指令。

按模板加载校验规则。新闻模板保留来源、证据等级和事件影响或品种走势分析；版本发布模板可使用版本号与变更内容；告警模板可使用对象、触发条件、观测时间和状态。无法通过校验的任务留下跳过或失败记录。

## 模型与运行审计

独立管理供应商、服务地址、模型名称、密钥引用、超时、并发、额度和重试限制。工作区可选择默认模型，Bot 或订阅可在授权范围内显式覆盖；有效配置优先级为订阅、Bot、工作区和全局默认。一次处理绑定完整配置快照，避免重试时静默切换模型。

同一工作区如果通过不同 Bot 选择了不同模型或模板，应生成不同处理任务；只有有效处理配置一致时才共享结果。去重键包含工作区、事件版本和处理配置版本，而非只包含事件编号。

运行器负责工具循环、最大步数、超时、取消和结果校验，并实际验证模型的工具能力。每次调用保存供应商、模型、可获得的模型版本、参数、提示词及规则快照、输入哈希、工具轨迹、用量和失败原因。密钥只保存在服务端，管理 API 返回配置状态而非原值。

回溯能够还原当次输入和执行证据，不保证重新调用模型得到逐字相同的文本。无模型调用的任务也记录模板、处理规则和输入版本。

## 插件体系

首版采用内部注册表和配置结构，不开放自动执行任意远程插件。插件声明名称、版本、能力、配置及生命周期。

- 来源插件：RSS、网页变更、API、Webhook 等输入。
- 模型适配器：统一模型请求、工具调用、用量、错误和取消。
- 处理与工具插件：模板转换、确定性筛选、工作区文件工具或有明确权限的扩展处理。
- 平台适配器：平台账号连接、协议、必要回调及能力声明。
- 消息渲染插件：按平台生成文本、卡片等目标格式，并处理长度限制。

来源和平台可以分别扩展。停用插件不清空历史记录；插件版本进入运行快照，便于追查行为变化。

## Web 信息架构

管理页统一使用“订阅推送工作台”，提供：

- 概览：来源健康、待处理事件、运行中任务、投递结果和模型用量。
- Bot 管理：按“命名与类型 → 分类配置 → 自动绑定本地工作区”接入真实机器人；查看连接、扫码登录、推送目标、目录、启停和发送记录。
- 平台能力：查看适配范围和连接能力；账号认证、连接状态及接收目标在机器人详情中管理，不要求先到独立账号页创建。
- 工作区：左侧选择本地目录，右侧管理独立 AI 配置、订阅分配及绑定机器人；由接入流程自动创建或绑定。
- 来源与订阅：输入配置、轮询或事件接入、筛选及推送策略。
- 模型：服务配置、工具能力检查、并发及额度。
- 插件：版本、能力、启停及依赖状态。
- 运行与回溯：输入、处理、模型工具记录、派生产物和每路投递状态。

通用页面使用“内容”“事件”“处理结果”和“推送记录”等用语。新闻分类与“新消息快讯”出现在选用新闻场景的订阅与产物中。

## 事件与投递流程

1. 调度器领取到期来源，或已认证回调产生输入；请求前检查同站间隔、冷却及来源限额。
2. 来源插件生成标准事件，按外部 ID、版本、内容变化或规则条件判重，分别建立初始基线。
3. 保存原始输入、来源标识、观测时间、可获得的发布时间、证据范围和内容哈希。
4. 根据工作区订阅、规则及推送策略生成处理任务，保存有效配置快照。
5. 按模式直接生成、规则转换或由 Agent 整理；工作区间分别处理，配置相同的目标复用标准产物。
6. 按内容模板验证字段、证据及筛选结果，跳过与失败均留下记录。
7. 对每条路由分别生成平台派生产物及投递任务，检查平台能力、上下文与限流后发送。
8. 保存各路回执并关联展示完整证据，互不覆盖发送状态。

生产投递直接调用对应平台的真实发送接口，不设置模拟投递模式。投递状态保留明确失败、通道接受和 UNKNOWN 的区别。旧 ADAPTER_ACCEPTED 状态按迁移规则保留或显式映射，旧验证回执只读保留且不计入真实投递成功数。通道接受不等于用户收到或已读，UNKNOWN 不自动重发。

投递去重键包含事件版本、处理结果及具体路由。目标、账号或所属工作区发生变化时，不将旧待投递内容自动发往新目标；历史快照保留，未发送任务取消或按明确迁移规则处理。

## 迁移顺序与验收

第一阶段迁移现有来源、限流、队列、隔离和测试，建立独立可启动服务及标准事件。第二阶段完成独立模型运行器、处理模式、管理登录、机器人三步接入和本地目录自动绑定。第三阶段扩展来源类型及多平台适配器，按平台矩阵逐个验收。现有新闻订阅是首个兼容场景，不能继续成为核心对象或全站固定模板。

功能验收从新增真实机器人开始，覆盖扫码类和参数配置类接入、独立目录自动创建、共用目录绑定、至少两类内容、多个 Bot 和两种真实平台通道。核对共享输入、按工作区或不同配置处理、平台格式转换和每路实际发送结果。失败、限流、超时、UNKNOWN、基线和重启恢复由开发测试验证，不作为用户可选的机器人类型或投递通道。未经真实测试的平台保持规划或适配状态。

隔离验收覆盖工作区路径、规则快照、私有来源缓存、账号权限与路由绑定。模型测试验证工具调用和产物保存，规则转发测试验证无模型调用也可完成。现有新闻的分类和证据校验作为场景测试保留。

切换前暂停旧实例采集、处理与发送，确认在途任务，再进行版本化数据迁移。记录旧 tenant ID、UMO 和文章任务到新工作区、账号、目标和内容事件的映射，不因重命名直接搬移正在使用的目录。保留已处理记录、历史基线和 UNKNOWN，避免重复推送。

模型凭据和平台登录状态分别迁移验证，不从工作区 ZIP 推定完整。最终在 AstrBot 停止时验证独立启动、管理登录、新事件触发、真实模型处理、多平台发送、重启恢复和历史回溯；正式投递由唯一实例负责，旧实例保留回退能力。
