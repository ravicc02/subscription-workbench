# 对话与发布并行

状态：v0.5.0 源码实现；本机 6190 实例已备份并加载本轮媒体入站改动。发布标签不等于其他实例已部署。

## 处理边界

- 微信、Telegram、QQ 官方和飞书应用把稳定 ID 的文本及支持的图片、语音、视频消息送入对话队列；媒体细节与限制见 media.md。QQ、飞书私聊可直接提问；群聊需 @机器人，普通群消息仅发现目标；Telegram 群聊还允许回复机器人。仅已选择的目标入队，其他平台仅提供投递。
- 轮询通道的入站消息与平台游标在同一个 SQLite 事务提交；QQ/飞书长连接事件接收后持久化，但 SDK 的事件确认与本地提交不是一个分布式事务。重复事件以 bot ID + 平台消息 ID 去重。重启时处理中恢复排队，发送中变为 UNKNOWN，不自动重发。
- 发布整理有一个 worker，对话有两个 worker；发布与对话共享两个模型任务名额。不同会话可以并行处理，发布正在运行时仍有一个对话名额；两个对话占满名额时发布排队等待。同一会话按入站顺序处理，上一条回复获通道接受或终止后才开始下一条。回复与推送共用单一发送 worker，回复优先，已有分片推送不会中途插入回复。
- 会话键包含 bot、平台、接收目标；群聊按提问用户隔离，Telegram 还区分话题。上下文取最近六轮已接受的问答、较早问答的截断摘录及当前目标近期三条已接受的推送。全部入站及回复状态在数据库保留；`ADAPTER_ACCEPTED` 只表示通道接受，不表示用户收到或已读。
- 对话模型优先级：机器人覆盖、工作区覆盖、全局默认对话模型。没有对话模型时明确失败，不暗中借用发布模型。发布模型仍沿用订阅、机器人、工作区、全局默认的既有优先级。
- `search_pushes` 仅查当前 bot、目标、工作区已接受的历史产物；每轮最多两次、各查近期 100 条，返回最多五条。外部内容不是系统指令。
- `search_web` 和 `fetch_page` 必须全局启用检索服务且工作区允许联网，默认无权限。支持 SearXNG JSON 或 Brave Search API；每轮最多搜索两次、抓取三页。只能打开该轮搜索结果 URL，所有请求逐跳经过现有 URL/DNS/私网限制，使用已保存的代理地址、超时及响应预算。私有 SearXNG 地址须由管理员显式设为允许主机。搜索失败时模型必须说明无法核实，实时行情仍需专用行情接口。

## 管理与回溯

“对话”页管理默认对话模型、搜索服务及入站回复流水；工作区 AI 面板配置对话模型和联网权限；机器人管理可覆盖对话模型。API 返回的搜索配置不包含密钥。工具记录仅保存名称、域名、摘要哈希、结果数或错误，不存明文检索词。

本机三个已有 bot（两个微信、一个 Telegram）处于已连接状态，Telegram 的现有 Token 通过 getMe 只读鉴权。正式库备份副本中，三个现有 bot 各用真实对话模型完成一条合成图片、语音或视频消息的排队、处理和回复投递；投递在副本内截获，没有触达真实平台。合成口语 Ogg/Opus 通过本地转写后，现有 Telegram bot 的对话模型正确回答“42”。真实媒体入站、微信/Telegram 平台回复与用户接收情况仍需从用户端发消息验收。

## 尚未实现

长期语义摘要、回复与快讯之间可配置的速率预算、Discord/Slack/OneBot 等平台的双向接入，以及实时行情专用数据工具。媒体生成、语音合成和整段视频理解尚未实现；QQ/飞书媒体入站仍需真实账号验证。
