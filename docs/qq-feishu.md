# QQ 官方与飞书应用机器人接入

本项目的 QQ 官方机器人与飞书企业自建应用通过长连接收事件，通过各自官方消息 API 发送文本。它们与 OneBot v11、飞书群自定义 Webhook 是不同接入类型。参照 AstrBot 的接入场景与事件形态，代码使用 `qq-botpy==1.2.1` 和 `lark-oapi==1.7.5` 独立实现；不依赖或复制 AstrBot 运行时。

## QQ 官方机器人

QQ 开放平台的[消息接口说明](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)注明自 2025-04-21 起主动推送接口下线。这里的 QQ 接入仅用于接收消息及在平台允许的时限内被动回复；不会进入订阅推送队列，也不提供主动测试消息。WebSocket 能否在具体账号继续接入，仍需用真实应用实测，不能仅凭 AppID/AppSecret 预检判断。

1. 在 QQ 开放平台创建机器人，取得 AppID 和 AppSecret，并开放实际使用的私聊、群聊或频道消息事件与权限。
2. 在工作台新增机器人选择“QQ 官方机器人”，填写凭据。保存时验证临时令牌，不保存临时令牌；成功后自动绑定本地工作区。
3. 启动 QQ WebSocket 后，向机器人发送一条私聊消息或在群中 @机器人。目标会出现在机器人详情中；第一个目标默认选中，其余目标需要手动勾选。
4. 选择工作区后向机器人发送一条消息，验证被动回复与会话记录；QQ 不作为订阅快讯的主动接收目标。

接收目标分别记录为 `c2c:<openid>`、`group:<openid>`、`channel:<id>` 或 `dm:<guild_id>`，不互相混用。私聊与明确 @机器人的群消息进入对话队列；普通群消息只用于发现目标。对话回复在原消息有效时带原消息 ID，超出窗口或无入站消息 ID 时明确失败，不尝试主动发送；平台拒绝标为 FAILED，结果不明标为 UNKNOWN，不自动重发。QQ 官方机器人不是个人 QQ 扫码登录。

## 飞书企业自建应用

1. 在飞书开放平台创建企业自建应用，启用机器人能力和“使用长连接接收事件”，订阅 `im.message.receive_v1`，授予接收和发送消息所需权限，发布应用并让目标用户/群可访问。
2. 在工作台选择“飞书应用机器人”，填写 App ID、App Secret。保存时验证租户令牌与机器人身份，成功后自动绑定本地工作区。
3. 向应用机器人发一条私聊消息或在群中 @机器人，发现飞书 `chat_id` 目标，再选择订阅范围与测试发送。

飞书消息发送以 `chat_id` 为目标，使用稳定的请求 UUID；成功必须返回 `message_id`。普通群消息不会进入对话队列。飞书群自定义 Webhook 仍是单向投递，不能替代企业应用机器人。

## 运行边界

- 当前接收文字、图片、语音和视频，图片进入多模态对话，语音使用平台或本地转写，视频只抽取两帧；只发送文字回复和文字订阅推送。媒体协议已有隔离测试，真实 QQ/飞书账号的入站与回复尚未验收，详见 `docs/media.md`。
- 服务需保持运行，长连接断开后有状态与重连退避；停止或重新绑定机器人时旧连接会取消，旧绑定事件不接受。
- 入站 ID 去重、目标独立选择、队列和回执使用既有持久化机制。`ADAPTER_ACCEPTED` 仅表示接口接受，不能证明用户已读。
- 本地测试覆盖官方令牌/消息接口的隔离协议、长连接生命周期和 QQ 对话链路。没有真实 QQ/飞书应用凭据时，不能声称完成了线上入站、群权限或飞书真实主动推送验收。
