# 非 RSS 订阅源扩展方案

状态：方案，未实施。本文不表示任何社交平台适配器、授权或持续采集已通过验收。

## 目标与边界

国内社媒、海外社交平台、邮件和合作方事件不必先转换成 RSS，均可作为订阅源。工作台统一负责建立历史基线、调度、断点续采、去重、存证、工作区分类/标签匹配、处理与投递；获取内容所需的账号授权和平台规则由具体连接器承担。现有 RSS、静态网页、公开 JSON API 和 Webhook 继续工作。

MCP 是 Agent 发现和调用工具的协议，不等于持续订阅系统。可以将经过审核的 MCP 只读工具交给对话 Agent 做按需查询；定时采集、游标、重试和订阅匹配仍由服务端持久化调度。不得让 Agent 自行保存平台 Cookie、执行任意命令或把一次搜索结果当成推送基线。

## 连接模型

```text
官方 API / 授权连接 / RSSHub / 邮件 / 外部工作流
               -> 拉取适配器或签名 Webhook
               -> 标准内容事件与原始证据
               -> 基线、游标、去重和权限域缓存
               -> 来源分类/标签 -> 工作区订阅 -> 处理 -> Bot 投递

受控 MCP / 搜索工具 -> 对话 Agent 的按需查询，不替代上述采集队列
```

将“连接”与“订阅源”分开：一个连接保存某个平台的本地授权状态、能力和额度，可供多个来源使用；一个来源只配置该授权范围内的账号、话题、关键词或栏目以及分类/标签。工作区继续按分类和多个标签订阅，多个 Bot 绑定同一工作区时复用可共享的输入与处理结果。不同账号可见范围、不同授权或私有来源不能仅按 URL 合并缓存。

连接器需声明 `pull`/`push`/`query` 能力、认证方式、授权范围、最小采集间隔、媒体和正文能力、限额与失效处理；实现配置验证、增量拉取与游标提交，或验证签名后接收事件。统一事件至少包括平台、来源与授权域、稳定外部 ID、内容版本、原文链接、作者/账号、发布时间、首次观察时间、文本与媒体引用、内容完整度（全文/部分/摘要）和原始证据哈希。视频标题不能冒充视频全文；转录必须另行授权和处理。

首次接入只建立历史基线。游标和入队状态一起持久化；更新、删除和重复投递分别处理。429/403、超时和配额耗尽进入按平台/账号的冷却，保留来源健康度、上次成功时间和可定位的失败原因。外部工作流通过每连接单独密钥的签名 Webhook 入站，限制大小、时间窗和重放；不能直接写入投递队列。

## 候选渠道

| 渠道 | 方式与前提 | 产品承诺 |
| --- | --- | --- |
| 微博 | 先核对官方 CLI/开放能力可提供的只读检索、账号内容和热榜，以及实际授权范围 | 在账号与接口真实可用后试点；不授予 Agent 任意命令执行 |
| X | 官方 API 的近期搜索或账号内容接口，按账户/关键词配置来源 | 以开发者权限、费用、时间窗口和限流为准，不承诺免费或无限历史 |
| 抖音 | 官方开放平台/MCP 能力以及授权账号或经批准的搜索能力 | 先申请并验证权限；不把任意账号、任意视频的完整采集作为默认能力 |
| 小红书 | 核对自身授权账号、商家/合作方接口的范围 | 先做可行性试验；不承诺存在任意公开笔记的通用订阅接口 |
| 非 RSS 公开站点 | RSSHub 路由、现有网页/API 适配器或受控合作方 Webhook | 每个路由单独验证可访问性、原文和条款，第三方路线标明维护风险 |
| 邮件与外部工作流 | 专用收件箱、邮件服务事件，或 n8n 等工作流转签名 Webhook | 由用户授权并保留消息来源；工作流不拥有工作台投递状态 |

不要以规避登录、验证码、频率限制或平台风控作为正常采集方案。授权不可得、条款不清、正文不完整或长期 403/429 的路线，应停止试点或降级为人工提供的线索，不默默宣称采集成功。

## 管理与发布设计

管理页增加“连接”作为来源的前置对象，显示授权主体、作用域、有效期、额度和最近错误。新建来源时选择渠道与已有连接，填写账号/关键词并预览近期样本，再选择分类和标签；启用前说明首次基线不回推历史。按需查询的 MCP 服务需独立登记、允许列表和工具权限，默认不提供写入或账号管理能力。

公共订阅包可包含提供商标识、公开匹配条件、分类/标签及建议间隔，不含令牌、Cookie、私有消息、连接 ID 或历史游标。导入时先预览范围和权限需求，再在本机绑定连接；未完成授权不得自动启用来源。改变包格式须单独升版并保留 v1 的导入能力。

## 建议实施顺序与验收

1. 固化连接器契约、标准事件、授权域缓存和签名入站，保持现有来源配置兼容；用隔离数据验证首次基线、断点续采、重放、撤权及限流。
2. 选一个官方授权渠道和一个外部工作流作为端到端试点，例如微博/X 中权限可用者与 n8n 签名 Webhook；先跑持续观察，再纳入管理页和订阅广场。
3. 抖音、小红书分别完成账号/应用权限、接口字段、可用正文、配额、条款和目标网络验证后才决定是否开发正式适配器。MCP 只作为对话检索试点，不能用它替代采集证据。

每个试点需连续观察至少 7 天：新内容到达延迟、成功率、重复/漏采、正文完整度、429/403、授权失效、成本、跨工作区数据隔离和真实投递回溯。没有足够证据时标记“实验中”，不写成“已支持”。
