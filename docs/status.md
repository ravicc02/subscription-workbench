# 当前实现与验证

版本：0.4.0。验证日期：2026-10-24。发布标签不会部署到运行实例。

非 RSS 社媒及连接器扩展仅为方案，尚未实现或完成平台授权验证，见 `docs/source-connectors-plan.md`。

订阅源列表的“检查全部”会按原有间隔、同站限流与冷却逐项执行正常采集；仅包含已启用的 RSS/网页/API 来源，跳过暂停和 Webhook。它可能将新事件送入整理与推送队列，不等同于只测试网络连通性。任务在服务端持久化，最多同时检查 3 个来源，页面展示进度、逐来源结果和最近 10 次任务；刷新或关闭浏览器不会中断。停止仅取消未开始项目，服务重启会恢复排队项目，已开始但结果不确定的项目标为“中断待核实”且不自动重试。已有“检查所选”和采集状态筛选保留。

## 已实现

共享工作区创建支持命名，已有工作区提供独立重命名入口。名称更改同步显示到机器人和订阅，不移动目录或改写规则、产物及绑定关系。管理会话失效后，页面清除旧数据并返回登录，不继续轮询已失效的接口。

独立 Python 服务、独立管理登录、React 管理页面、实际本地工作区绑定、来源轮询、事件接入、独立模型工具运行器和逐目标真实投递队列已经建立。运行不需要 AstrBot 进程或 Python 包。

新增机器人按三步操作：命名与类型、按平台配置、自动绑定目录。支持独立目录、默认共享目录和已登记目录。已有规则和产物保留，登录凭据与发送状态按机器人分别保存。

当前可选接入类型是个人微信二维码、Telegram Token、Discord Bot、Slack Bot、OneBot v11 HTTP API、飞书群自定义机器人、企业微信群机器人、钉钉自定义群机器人和 HTTP Webhook；飞书/企业微信/钉钉完整应用机器人等其他平台仍标为规划中。Discord 验证 Bot 身份并读取频道，Slack 验证 Bot 身份，OneBot 验证登录账号；这些检查不能替代目标写入权限或真实账号投递验收。三类群机器人和 HTTP Webhook 保存后状态为“已就绪”，实际可发送性由真实请求及其返回验证。

来源支持 RSS / Atom、网页内容变更、JSON API 和带独立凭据的 Webhook。新建订阅绑定一个工作区、一个大类及多个标签，标签下的多个来源按并集动态匹配；同一实际工作区的机器人共享处理结果并分别投递。历史指定来源订阅仍运行，编辑时需显式改选分类和标签。每个来源的新内容分别触发处理。规则处理目前提供关键词筛选和长度约束；没有可视化任意规则编程。轮询保留历史基线、同站限流及持久化冷却。

订阅广场提供金融、科技、GitHub Hot 三类内置公开来源包，可预览、增量导入，也可导入/导出规范 JSON；包含 RSS、网页和公开 JSON API，Webhook 仅在本地配置。单分类包只显示包名，来源明细默认收起。预览区区分完全匹配的已有来源和仍需补齐分类/标签的来源；同步后打开新增订阅并预选单分类包的分类，已同步的包可直接创建订阅，但不会自动保存或推送。分类和标签可增删改；来源归属一个分类并可带多个标签。40 个预置 RSS 依照 `docs/default-taxonomy.json` 首次归类到金融市场和国际时政，已有人工分类不覆盖；GitHub Hot 来源保留原分类。多标签取并集，命中多个标签的同一来源不会重复处理，新来源首次检查仍只建历史基线。具体格式见 `docs/subscription-package.md`。GitHub Hot 社区聚合 RSS 不带发布时间，显式允许无日期条目并以首次基线保护历史；网页趋势仅作为页面变更事件，不解析逐个仓库。

处理支持直接转发（不调用模型，截取提取内容）、规则处理（不调用模型，关键词筛选与长度约束）和 Agent 整理（按工作区 AI 配置调用模型）。界面按处理方式展示说明，只有 Agent 模式展示模型和 AI 补充要求。模型当前使用 Chat Completions 兼容工具接口。工作区规则按任务快照记录，文件工具限制输入和输出范围，质量不合格时最多两次修正。外部输入不作为权限指令。

Telegram 认证、消息轮询及发送自动复用采集网络中已保存的代理地址，不配置时直连。采集全局开关只影响来源的继承策略，即使该开关关闭，Telegram 仍使用保存的代理地址。模型和其他通道不受此策略影响。接入失败的 Token 作为加密草稿保留；未验证的草稿不会替换已验证账号的发送凭据。

凭据加密存入 SQLite，密钥单独保存在本地状态目录。公共工作台接口不返回凭据。工作线程具有状态目录进程锁，重启时恢复未完成整理，并将发送中断标为 UNKNOWN，不自动重发。

本版本新增微信/Telegram 文本入站和两个对话 worker。入站与游标原子提交，按 bot、目标及群聊用户/话题隔离；不同会话可并行，同一会话按入站顺序处理。发布整理与对话共享两个模型任务名额，回复优先进入已有单一发送 worker。全局、工作区、机器人可分别绑定对话模型；工作区可设置对话提示词和联网权限。历史推送仅能查本 bot/目标/工作区已获通道接受的产物；SearXNG 或 Brave Search 受全局和工作区双重开关限制。对话并发和尚未支持的平台见 `docs/conversations.md`。

正文及来源请求按每一跳实际请求的 URL 所属站点（非原订阅源站点）共享间隔与冷却。正文跨站跳转在请求前校验来源允许域名。站点暂缓只延后整理任务、保留待投递；到期自动重试，五次暂缓后记录失败。旧任务表增量迁移 `next_try` 字段；不重置历史发送状态。

暂停来源或订阅会取消已入队但失去全部有效订阅的任务及未发送投递；同一任务仍被其他启用订阅使用时继续保留。处理和投递前再次核验来源及订阅的当前状态。运行记录在页面可见时每 10 秒刷新，延后任务展示“等待重试”、下次尝试时间及次数。

上述改动已在隔离实例和正式数据的备份副本验证；本次发布流程不重启任何运行实例，实际运行版本需在实例中单独核对。

来源分类/标签改变时，已入队但不再匹配的订阅边和待投递任务立即取消；仍有其他有效订阅的共享任务保留。旧数据库的订阅关联只在首次创建关联表时迁移，不会在重启后把已删除的订阅关系重新恢复。

企业微信群文本按保守的 UTF-8 字节预算分片，发送前再次校验单条消息大小；报告缺失、损坏或超出 12 片上限时，投递明确失败并记录原因，不再在待发送队列里反复触发异常。

## 实测证据

- 117 项自动化集成与回归测试通过，覆盖登录鉴权、配置版本、目录保护、共享处理、分类多标签动态路由、Webhook 事件、实际 HTTP 发送、未知结果、429 冷却及微信、Telegram、Discord、Slack、OneBot、飞书/企业微信/钉钉群机器人协议适配；新增覆盖批量检查的持久化、鉴权、进度、取消和重启恢复，跨来源正文站点冷却、逐跳重定向限流、未允许正文域名阻断、重启后继续重试、重试上限与旧任务表迁移，以及来源和订阅暂停后的队列取消与发送前复核。对话新增覆盖入站游标原子提交、去重、群聊隔离、不同会话并行与同会话顺序、模型并发上限、回复优先、UNKNOWN 重启保护、历史推送隔离和受控搜索工具。
- 浏览器验证覆盖首次设置与登录、会话失效自动回到登录、三步接入、共享和独立目录、广场单分类去重、来源明细折叠与窄屏展示、同步后直达订阅及已同步包快捷入口、分类与多标签选择、自动匹配来源预览、处理方式切换、真实本地 HTTP 推送及回溯；工作区 AI 配置、慢请求反馈与防重复、跨页面操作记录、批量暂停和删除，以及采集代理配置与真实隧道测试也通过。隔离实例验证了批量检查离开页面、刷新后查看持久化结果，以及未来重试任务在运行记录中的时间、次数及原因展示。
- 本轮先在线备份本地数据库和密钥，再对数据库副本与 6190 本地实例执行预置源分类：金融市场 13、国际时政 27、原有 GitHub Hot 4；19 个停用的测试 Webhook 仍未归类。17 条现有订阅、3 个机器人以及历史任务和投递数保持不变。浏览器交互与 HTTP 推送在隔离实例中验证，未向真实账号发送测试消息。
- 当前本机代理地址已保存，采集全局开关关闭。使用假 Token 的 Telegram 探测通过该代理到达官方 API 并收到 HTTP 401；它只验证网络路径，不验证真实 Bot 账号或实际发送。
- 公开美联储 RSS 可以访问，观察到 15 条条目。GoldSeek 在本机当前网络中直连超时，保持冷却，不表示预置的 40 个来源均可达。
- 迁入模型原标识 `deepseek-v4.1-flash` 返回 404。通过服务端模型目录确认 `deepseek-v4-flash` 可用，独立项目改用此标识；原 AstrBot 配置保持原样。
- 真实模型通过工具能力检查。公开 RSS 历史样本经过一次正文采集、两个工作区独立模型处理、三个实际本地 HTTP 接收请求。三个投递均获接受，共用目录的两个目标内容一致。
- 样本为美联储 2026-10-13 发布的会议纪要，保留原始发布时间；作为隔离的历史验证输入使用，没有作为刚发布新闻进入正式订阅。
- 微信接口能生成有效登录二维码。扫码确认、用户会话维护和实际微信投递仍需要使用真实账号验证；本轮未向客户微信发送。
- 正式库的“处理”模型 `deepseek-v4.1-flash` 与“对话”模型 `gpt-6-sol` 在隔离状态完成真实调用：合成事件整理为 RENDERED，对话追问生成 READY，两个产物分别通过本机 HTTP 接收端，均为 ADAPTER_ACCEPTED。最终复测的报告与回复位于 `runs/verification/live-role-20261024-004/result.json`。不代表真实平台账号收到了消息。

开发验收数据及截图位于 `runs/verification/`，该目录不进入源码仓库。`live-services.json` 记录真实模型与二维码检查，`live-pipeline.json` 记录真实来源、模型任务及 HTTP 投递。浏览器结果记录在 `browser.json`。

## 尚待扩展或外部验证

- 使用真实账号完成微信扫码后的登录、上下文和发送验收；Telegram 需要真实 Token 与接收会话验证。
- Discord/Slack 与飞书/企业微信/钉钉群机器人目前只有协议级模拟验证，OneBot 在本地 HTTP 测试服务完成登录和实际 HTTP 提交；均未以真实平台账号完成端到端验收。其余平台逐项实现接入与真实发送，再开放到新增机器人类型。
- 合并窗口、静默时段、可配置汇总、额度管理和更完整的格式渲染尚未实现；当前有效新事件即时处理与推送。
- 带认证的私有 API、通用阈值表达式及长期语义会话摘要不属于当前已完成范围；近期会话历史已持久化。
- 原 AstrBot 实例的历史队列和账号状态没有自动切换；正式上线迁移须单独执行版本化迁移并确认唯一发送实例。

本轮验证不修改正式实例的机器人、订阅、工作区、登录状态及模型；浏览器验收在独立状态目录中执行。历史失败的 Telegram 记录若没有保存 Token，需在“修改接入配置”中重新输入。来源仅在明确选择代理或开启采集全局代理后才使用已保存的代理。
