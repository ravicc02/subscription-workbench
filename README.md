# 订阅推送工作台

独立运行的订阅、内容处理与多平台推送服务。后台、模型运行器、登录和管理页面不依赖 AstrBot 进程。

## 当前版本

- 机器人接入：个人微信二维码、Telegram Token、Discord、Slack、OneBot v11 HTTP API、飞书/企业微信/钉钉群机器人和 HTTP Webhook。新通道已通过隔离协议或本地 HTTP 测试；实际账号投递仍需对应平台凭据验收。
- 三步创建：命名与类型 → 平台配置 → 自动绑定本地工作区。未实现的平台只在兼容目录展示，不出现在可选类型中。
- 本地工作区：默认独立目录，也可绑定共享目录或已有目录。同一实际目录登记为一个工作区，不覆盖已有文档。
- 输入：RSS / Atom、网页内容变更、JSON API 和带独立凭据的 Webhook 事件。
- 处理：直接转发、关键词筛选与长度约束、独立 Agent 工具循环。Agent 关注范围、排除内容、整理要求和模板在工作区页面配置，按任务保存版本快照。
- 调度：首次历史基线、来源错峰、同站间隔、持久化 429 / 403 冷却。
- 推送：真实平台接口、按目标独立状态、消息分片；发送结果不明时停止自动重发。
- 回溯：原始输入、处理结果、推送内容、规则快照、模型用量与工具轨迹。
- 管理：独立密码登录、服务端加密凭据、工作区 AI 配置、模型配置及工具能力验证。

预置 40 个公开 RSS 来源配置，只有被有效订阅引用时才自动轮询。配置数量不代表这些来源当前全部可达。

## 本地启动

需要 Python 3.11 或以上，以及用于构建管理页的 Node.js 和 pnpm。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
pnpm --dir web install --frozen-lockfile
pnpm --dir web build
.\start.ps1
```

浏览器访问 `http://127.0.0.1:6190`，首次使用设置管理员密码。已有本地开发环境可直接执行 `start.ps1`。

Linux 或其他环境启动：

```sh
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 6190
```

默认只绑定本机，不提供远程公开入口。一次只运行一个任务工作进程，同一状态目录的工作线程具有进程锁。

## 接入机器人

1. 新增机器人，填写名称并选择类型。
2. 根据类型扫码或填写参数。微信登录成功后，需要向机器人发一条消息建立接收上下文；Telegram 可填写会话 ID，也可在收到消息后从发现列表选择；Discord 填写 Bot Token 和频道 ID；Slack 填写 Bot User OAuth Token 和频道/会话 ID；OneBot v11 填写 HTTP API 基础地址、群聊或私聊及目标 ID；飞书、企业微信、钉钉群机器人填写各自的官方 Webhook（飞书和钉钉可填签名密钥，钉钉可填安全关键词）；HTTP Webhook 填写接收地址。
3. 系统自动绑定本地目录并初始化规则。默认使用 `workspaces/bots/<bot-id>/`，共享模式使用 `workspaces/shared/`。可以绑定已经登记的目录。

新建共享工作区时可以填写中文或英文名称。已有共享工作区可在工作区页头点击“重命名”，所有关联机器人及订阅同步显示新名称，本地目录及历史内容保留。

创建页面的“本地工作区设置”可指定目录；目录始终属于运行服务的主机。工作区创建后，在“订阅”中可选择多个来源和一种处理方式。每个来源的新内容分别触发处理；若需要不同规则，应分成多个订阅。首次采集仅建立历史基线，后续有效事件才触发推送。

“订阅广场”内置金融、科技和 GitHub Hot 订阅包，包含 RSS / Atom、网页变更和公开 JSON API 来源；也可导入或导出规范 JSON。导入只同步本地来源及分类标签，不创建订阅、不自动推送。来源页可增删改分类与标签，一个来源属于一个分类并可带多个标签。订阅可选择一个分类及多个标签（不选标签则匹配整个分类、多个标签取并集），后续归类的来源也会纳入；或沿用手动指定多个来源。Webhook 保留本地配置，不进入可分享的订阅包。详细格式与边界见 `docs/subscription-package.md`。

平台账号信息在机器人详情中管理。“发送测试消息”实际向所选目标发送。

Discord/Slack 的身份认证与目标配置使用官方 API；Discord 还会读取频道信息。频道写入权限、Slack 的 `chat:write` 权限与实际可达性只有发送后才可确认。OneBot v11 要启用 HTTP API 和 `/get_login_info`、`/send_msg`，本地私有地址默认不允许任意外呼；在可信网络中可用 `WORKBENCH_ALLOWED_HOSTS=127.0.0.1` 显式允许本机服务。不要将 OneBot HTTP API 无认证暴露到公网。修改通道凭据或目标后，未发送的旧绑定任务会取消，不会误投新目标。

飞书“群自定义机器人”只向该 Webhook 所在群发送文本，不是飞书应用机器人，也不支持从飞书会话发现目标。保存配置只校验官方域名与可达性，状态为“已就绪”；必须向该群发送测试消息，才能确认 Webhook 密钥、签名校验及群内发送权限。签名密钥更换后未发送任务会取消。推送内容中的 `<at>` 提及标记会转义，避免来源文本触发全员提醒。

企业微信群机器人和钉钉自定义群机器人同样只向 Webhook 所在群发送文本，分别调用各自接口并检查业务返回码，不能代替完整的企业应用接入。钉钉加签在每次发送时生成时间戳与签名；若群机器人采用“自定义关键词”安全设置，可填写关键词并前置于每条推送。保存配置只代表地址格式与网络可达，实际发送需在对应群中用“发送测试消息”验收。Webhook 地址包含凭据，工作台只在服务端加密保存，不要分享到订阅包中。

此前接入失败的 Telegram 机器人如果没有保存 Bot Token，需要在机器人详情的“修改接入配置”中重新填写一次；后续失败会保留加密草稿供重试。不要把 Token 粘贴到聊天里。

## 批量管理与采集网络

机器人、订阅源、订阅和模型列表支持多选；可批量启停、检查或删除适用的项目。删除只移除配置、关联订阅及未发送任务，保留本地目录、产物和历史；正在整理或发送的关联项目会阻止删除。仍绑定机器人的工作区需先改绑或删除机器人。

“刷新”“检查”等手动操作立即显示进行中状态，阻止同一请求重复提交。顶部操作记录在页面切换后继续显示结果；批量检查显示进度，正常轮询间隔和冷却会如实提示。

在“采集网络”配置 HTTP 或 SOCKS5 代理及可选认证。全局默认代理可关闭，单个订阅源可以选择跟随全局、始终直连或使用已配置代理。Telegram 的认证、收消息和发送自动复用已保存的全局代理地址，即使采集全局开关关闭也会使用；未保存代理时尝试直连。模型及其他机器人通道不受影响。代理失败不会退回直连，也不清除原站限流。可选的远程 DNS 通过代理访问 Cloudflare DoH，再校验并固定公网目标 IP。测试可达性不入队、不推送，并检查 RSS / JSON 格式。

## 模型与规则

模型接口支持工具调用形式的 Chat Completions 兼容服务。基础地址填写到 `/v1`；必须通过工具调用检查后再用于 Agent 订阅。凭据在服务端加密保存，不返回管理列表。

在“工作区”左侧选择本地目录，在右侧配置 AI 关注范围、排除内容、整理要求、推送模板和默认模型。订阅只选择来源、程序关键词及可选追加要求。每次入队保存配置快照，Agent 的读取工具按该快照提供本工作区规则，业务要求不再从可编辑的 AGENTS.md 文件读取。旧文档中的自定义要求迁入页面配置，原文件保留。Agent 仍只允许读取本次输入和规则，并写入指定产物。

可以在停止该独立服务后执行一次模型迁移：

```sh
python scripts/import-astrbot-model.py <astrbot-data/cmd_config.json>
```

迁移仅处理已启用的兼容模型服务，不迁移平台登录状态。原模型标识若已失效，需在模型管理中使用服务端实际提供的标识。

## 存储与配置

- `state/`：SQLite 队列、加密凭据、密钥、平台上下文、限流状态及公共输入缓存。
- `workspaces/`：实际本地工作区、规则、输入、处理结果、推送稿和运行证据。
- `web/`：独立 React 管理页。
- `docs/architecture.md`：完整目标方案。
- `docs/status.md`：已实现能力、验证证据及后续范围。

`state/` 中的数据库和 `vault.key` 必须一起备份。不要将凭据、登录状态、工作区或运行数据提交到源码仓库。

## 项目发布

源码、测试与前端一起在 Git 中管理，运行目录不进入仓库。每次推送 `main` 或提交 PR 会运行 Python 静态检查、自动化测试、前端构建和隔离浏览器验收。`vX.Y.Z` 标签通过相同检查后生成带前端构建产物的 ZIP 和 SHA-256 校验文件；发布包只含程序，不部署实例，也不迁移或覆盖账号数据。版本变更、打包、人工验收和回滚步骤见 `docs/releasing.md`，更新内容见 `CHANGELOG.md`。

可选环境变量：

- `WORKBENCH_ROOT`：服务状态和工作区所属项目根目录。
- `WORKBENCH_WORKSPACE_ROOTS`：额外允许绑定的工作区根目录，按系统路径分隔符分隔。
- `WORKBENCH_HOSTS`：允许访问的 Host 名称，逗号分隔，反向代理部署时显式配置。
- `WORKBENCH_ALLOWED_HOSTS`：明确允许请求的本地服务主机，默认空。用于本地模型或内网接收端，应限制到所需主机。

网络请求验证解析地址并固定连接到校验后的 IP，限制响应和解压体积。默认不请求私有地址，不复制旧实例的代理池或自动切换代理。

## 验证

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/check-browser.py
```

浏览器验收使用独立数据目录和真实本地 HTTP 接收端，不触碰用户平台账号。真实模型及公开来源的验收会产生模型调用费用，仅在需要时执行 `scripts/verify-live-services.py` 或 `scripts/verify-live-pipeline.py`。验证历史文章时保留原始发布时间并明确标记，不进入正式来源的补发流程。

后续平台接入、合并窗口、静默时段和额度管理见目标方案；它们未实现前不作为当前能力展示。
